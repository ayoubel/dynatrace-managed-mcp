# Classic dashboard workflows

The optional `service-health`, `infrastructure-health`, `incident-investigation` and `dashboard-update` MCP prompts produce guidance, not API execution or new permissions. They supplement the existing `continue_investigation` prompt; no scoring, Explain engine or tool authorization changes.

Dashboard prompts are available only in the `general` execution profile. Design prompts require the currently exposed `dynatrace_managed_validate_dashboard` tool. Incident design additionally requires `dynatrace_managed_explain_problem`. Update requires get, validate-update and update tools. Token-policy refresh updates prompt discovery; every prompt retrieval refreshes and checks permissions again. An explicit `create` request also requires the current create tool. Permission revocation can therefore reject a cached prompt. `incident-intelligence` continues to expose its read-only investigation tools/continuation without dashboard prompts. Without optional token-tool filtering, discovery follows the existing exposed tool catalogue; the underlying API and execution wrappers still authorize operations.

| Prompt                                     | Arguments                                                             | Behavior                                                                                                               |
| ------------------------------------------ | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `service-health` / `infrastructure-health` | `environment_alias`, `target`, `owner`; optional `mode`, `from`, `to` | Design by default; display window defaults to `now-1h` / `now`                                                         |
| `incident-investigation`                   | `environment_alias`, `problemId`, `owner`; optional `mode`            | Calls shared Explain V1 and presents only its findings/evidence; engine incident/baseline windows remain authoritative |
| `dashboard-update`                         | `environment_alias`, UUID `dashboardId`, `changes`                    | Explicit update: retrieve, preserve unrelated fields, validate, PUT to the same ID and verify                          |

`mode` is `design` or explicitly `create`. Select exactly one configured environment, never `ALL_ENVIRONMENTS` or a semicolon list. Prompts are user guidance: actual writes still require explicit user intent, available write tools and existing server authorization. Prompt retrieval itself performs no Managed API operation beyond the existing optional permission refresh.

`examples/dashboards/` contains private service-health, infrastructure-health and incident-investigation starting definitions. They intentionally have placeholder owners, entity-type-wide selectors and a last-hour filter. Replace `REPLACE_WITH_OWNER`, apply the actual requested entity/management-zone scope and display window, and discover/test real metric selectors before using them. Do not treat missing data as zero or these examples as ready-to-create dashboards. Local schema checks do not certify tile acceptance on any Managed version: target-environment validation is required before an explicitly requested write.

For incidents, obtain shared `dynatrace_managed_explain_problem` findings and use `dynatrace_managed_continue_investigation` only for follow-up clarification. Preserve unknowns, partial status and evidence references. Do not add a parallel diagnostic path or reinterpret evidence into an invented root cause. With read-only incident profile, use those tools directly and skip dashboard operations.

The three JSON examples, this document and four equivalent `.github/prompts/` workspace prompts are explicitly included in the package file list. MCP clients can choose prompts through their prompt picker. Workspace prompts are optional guidance and cannot bypass server permissions.

PUT replaces the complete definition. Fetch it immediately before edits, preserve unrelated settings and keep an export before substantial changes. Never blindly retry a timed-out write; inspect actual dashboard state first. Dashboard tool details are in [dashboard-tools.md](dashboard-tools.md). No live Managed verification is claimed by this documentation.
